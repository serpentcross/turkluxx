# TurkLuxx language layer

## Stage 1: content audit

The three public pages contain 231 distinct English text/attribute strings before
excluding proper names, addresses, social brands and numbers. The audit includes
hidden desktop/mobile blocks, ROI and citizenship dialogs, navigation, contact
labels, image alternatives, document titles, and callback forms.

Dynamic content resides in callback.js (validation and request status),
rengi-villa-explorer.js (villa descriptions, floor/room labels, CTAs, image
alternatives and announcements), rengi-istanbul.js (master-plan viewer),
rengi-antalya-data.js and rengi-antalya.js (project descriptions, statistics,
apartment types and viewer), and referral.js (invalid-link screen).

rengi-plans.js and its demo diagrams are not loaded by any public page and are
not in the public build; they are legacy, unpublished content.

## Architecture

Six flat JSON catalogs under locales/ use semantic keys. English remains the
source and fallback. Static HTML is kept as the readable English source. A shared
source-to-key binding reads the English catalog and updates individual text
nodes and accessible attributes in place. Original whitespace, inline markup,
paragraph classes, controls, listeners and structural data are retained.
An observer binds new nodes from the existing renderers. Parameterized dynamic
messages use TurkLuxxI18n.t(key, values, EnglishFallback). Never put HTML into
translations. Property names and backend lead values remain the existing names.
Dynamic renderers use TurkLuxxI18n.bind(element, key, values, attribute) when a
message depends on the current selection. Those bindings update without
re-rendering an explorer or resetting an open viewer. The bind values may be a
function, so floor names and selected-image labels follow the active language.
All six catalogs retain the original 361-key set. Keys, placeholders, numerical
figures, preserved brand names, nonempty values and UTF-8 decoding are checked
by scripts/i18n.test.mjs. Identical English values are allowed only for official
names or words that are also correct in the target language (for example Dutch
"Contact" and Spanish "Hospital").
The data-i18n-order hint reorders split phrases where Arabic or Spanish grammar
requires a different reading order, retaining their English order otherwise.

Language is stored separately as turkluxx_language. An optional ?lang=xx hint
overrides stored language for a landing visit. Language changes preserve every
other URL parameter and all referral keys. Failed locale loads use English;
blocked storage still permits switching on the current page.

Language paths and hreflang publication are deferred. Current Cloudflare assets
only map existing static filenames, and adding language paths requires asset
aliases or Worker routing, absolute asset URLs and localized SEO rendering.
Client-side ?lang=xx is a language hint, not a crawlable localized SEO page.
Canonical links retain the existing production page URLs. Do not advertise
hreflang until independently crawlable language URLs exist.

Arabic sets lang=ar and dir=rtl. Logical alignment/spacing rules cover text,
forms, selectors and cards. Media, floor-plan diagrams, measurements, phone
numbers and viewer controls retain their original orientation.
Arabic text uses Unicode bidi isolates around configurations such as 4+1,
measurements and phone numbers, preserving their visual order without changing
the catalog values. A few split homepage phrases use data-i18n-order so Arabic
and Spanish read naturally while retaining the existing markup and English keys.

Intentional untranslated content: brand/collection/proper names, postal address,
email/phone, URLs, unit identifiers, figures/measurements, and labels embedded in
existing raster plan/map images. Image pixels are unchanged; corresponding HTML
labels are translated. Backend emails and diagnostics remain English.

## Local verification

Run `npm.cmd test` and `npm.cmd run build` on Windows. Browser regression checks
use an existing local Chrome CDP endpoint on port 9227:
`node scripts/test-i18n-browser.mjs`. The script serves the project locally and
calls the unchanged Worker with a mocked email binding. It sends no real email.
`TURKLUXX_I18N_PORT` optionally selects a port other than 8799.
Screenshots are generated in the ignored build/i18n/ directory.

The browser matrix covers six languages, three pages, desktop and mobile,
language selectors, reload/navigation persistence, referral/sub query retention,
translated form validation/success/failure, and all villa media modes. Additional
checks exercise all Antalya projects, invalid referral screens, direct visitors,
canonical lead context, master-plan viewer, English leftovers and tracking-script
counts. See i18n-audit.json for the static source inventory; descriptions and
dynamic labels are cataloged under their property/common/media keys.
The browser harness disables cache, restores a controlled referral URL for each
language iteration, and waits for the dialog close event before reopening it.
English source HTML and technical data labels remain in the files deliberately
as inputs to the matching layer; the browser checks their translated output.
